# Фрагменты журнала изменений

Каждое изменение кладёт сюда **свой файл** вместо строки в общий `CHANGELOG.md`.

**Предмет живой, а не заимствованный.** До 8 сентября витрина обходилась без
фрагментов осознанно: свод говорил, что они окупаются там, где параллельные
ветки правят общий файл, «а тут один автор и одна ветка». За одну смену это
опровергли дважды — две ветки подряд встали с конфликтом в `HISTORY.md`,
потому что обе дописывали свой раздел в конец.

## Как добавить запись

```
changelog.d/<слаг>.<секция>.md
```

- **слаг** — что угодно уникальное, обычно имя ветки без приставки
  (`publish-missing-tile`, `russian-voice`);
- **секция** — одна из `added`, `changed`, `fixed`, `removed`, `internal`;
- внутри — **одна строка** текста: без ведущего дефиса и без имени секции, их
  подставит сборка. Номер изменения указывается в тексте — `(#170)`.

Пример, файл `publish-missing-tile.fixed.md`:

```
публикация картинок больше не падает на файле, который перестали рисовать: нет файла — нет копии, а не отказ всей раскладки (#170)
```

## Команды

```bash
python scripts/collect_changelog.py --check     # проверка формата, бежит в pr-check
python scripts/collect_changelog.py --preview   # как соберётся, ничего не меняя
python scripts/collect_changelog.py --collect   # перенести в CHANGELOG и удалить файлы
```

## Язык

По-русски, как и все служебные документы витрины: их читают владелец и окно.

## Чем это не является

**Фрагмент — не замена журналу решений.** `CHANGELOG.md` отвечает на вопрос
«что изменилось», `HISTORY.md` — «почему так решили». Первый читают, чтобы
узнать новости; второй — чтобы не переоткрывать закрытый вопрос. Запись о
причине не влезает в строку и не должна: для неё есть тело изменения.
